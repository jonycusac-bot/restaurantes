# CONTEXTO DEL PROYECTO: SISTEMA DE MENÚ QR PARA RESTAURANTES (OPEN SOURCE)

## 1. OBJETIVO DEL PROYECTO Y FASES
El objetivo final es desarrollar una plataforma de menú digital mediante código QR utilizando tecnologías modernas de JavaScript. El proyecto se abordará de manera incremental para mitigar la complejidad inicial:
*   **Fase 1 (MVP Actual):** Un sistema exclusivo de visualización de menú (catálogo digital). El cliente escanea el QR y solo ve categorías, platos, descripciones, alérgenos y precios. No hay carritos, ni pedidos, ni pasarelas de pago.
*   **Fase 2 (Escalabilidad de Negocio):** Transformar el sistema en un modelo SaaS (Multi-tenant). La base de datos y las rutas deben prepararse (o preverse) para albergar múltiples restaurantes independientes bajo una misma plataforma.
*   **Fase 3 (Interactividad):** Incorporar pedidos en tiempo real a la cocina (WebSockets) y pasarelas de pago o integración con WhatsApp.

## 2. PERFIL DEL DESARROLLADOR Y ENTORNO
*   **Tecnologías:** Entorno basado en Node.js y React / Next.js (ya instalados y listos en la máquina local).
*   **Disponibilidad de tiempo:** Limitada. 1 hora al día de lunes a viernes (para tareas atómicas, corrección de bugs o componentes aislados) y de 3 a 4 horas por día los fines de semana (para arquitectura, flujos complejos y despliegues). Total: ~8-10 horas semanales.

## 3. REPOSITORIOS DE REFERENCIA EN GITHUB
Se han evaluado dos estrategias principales basadas en código abierto para acelerar el desarrollo:
1.  **AtlasQR (ildrm/atlas-qr-menu-service):** Arquitectura SaaS robusta (Next.js, NestJS, PostgreSQL, Redis). Ventaja: Ya es multi-tenant y escalable. Desventaja: Curva de aprendizaje inicial alta para el tiempo disponible.
2.  **MenuQR (dustinwloring1988/menuqr):** Estructura monolítica más simple y directa basada en Next.js 14 y PostgreSQL. Ventaja: Resultados visuales rápidos (~2 semanas). Desventaja: Habrá que refactorizar la base de datos para hacerla multi-restaurante en la Fase 2.
